Payroll Enterprise System

Tentang Proyek Ini

Proyek ini dibangun secara mandiri, bukan untuk klien atau perusahaan nyata. Tujuannya untuk mempraktikkan langsung perancangan sistem yang menangani data sensitif: bagaimana merancang kontrol akses bertingkat, menyusun logika pajak yang kompleks, dan mengamankan data output — sekaligus jadi bahan sertifikasi BNSP Analis yang saya ambil.

Skenario Yang Diangkat

Berdasarkan riset terhadap pola umum di perusahaan skala menengah: tim HR sering menghitung PPh21 dan komponen gaji lain secara manual di spreadsheet terpisah per divisi, tanpa kontrol akses formal — siapa pun dengan akses file berpotensi mengubah angka gaji, dan slip gaji dikirim tanpa enkripsi lewat email. Skenario inilah yang saya simulasikan dengan data dummy untuk merancang solusinya: otomasi perhitungan yang akurat, kontrol akses bertingkat, dan distribusi slip gaji yang aman.

Arsitektur Sistem

Client mengirim request → API memvalidasi peran pengguna → payroll engine menghitung pajak dan berkomunikasi dengan database serta layanan enkripsi → slip gaji terenkripsi tersedia di portal karyawan.

Keputusan Desain & Trade-off

🔒 RBAC dibanding ACL sederhana

Perusahaan punya 4 peran (staf, manajer, HR, admin) dengan hak akses berbeda ke data gaji. RBAC dipilih agar aturan akses mudah diaudit dan ditambah peran baru tanpa mengubah logika inti, meski setup awal lebih kompleks dibanding ACL per-user.

🗄️ PostgreSQL dibanding NoSQL

Data gaji relasional dan butuh transaksi ACID ketat (perhitungan tidak boleh setengah tersimpan). PostgreSQL memberi konsistensi kuat; trade-off-nya skema lebih kaku saat kebutuhan berubah.

Tantangan & Solusi

Tantangan: aturan PPh21 punya banyak pengecualian (PTKP per status pernikahan, tunjangan tak kena pajak).

Solusi: memisahkan logika pajak ke modul terisolasi dengan unit test per skenario PTKP, sehingga perubahan aturan pajak tidak menyentuh kode inti payroll.

Tantangan: slip gaji harus terenkripsi tapi tetap cepat diakses karyawan.

Solusi: enkripsi dilakukan sekali saat pembuatan slip dan disimpan sebagai file terenkripsi, bukan dienkripsi ulang tiap request, sehingga waktu unduh tetap cepat.

Tumpukan Teknologi

Node.js TypeScript PostgreSQL RBAC Auth AES-256 Encryption

Yang Berhasil Dicapai

  • Sistem berhasil menghitung PPh21 secara akurat untuk berbagai skenario PTKP, tervalidasi lewat unit test.
  • Kontrol akses 4 peran (staf, manajer, HR, admin) berfungsi sesuai rancangan — diuji manual untuk tiap kombinasi peran dan aksi.
  • Slip gaji tersimpan dalam bentuk terenkripsi AES-256, mendemonstrasikan alur enkripsi end-to-end dari kalkulasi sampai penyimpanan.

Refleksi & Rencana Lanjutan

Karena ini proyek solo tanpa tim QA, pengujian masih manual untuk sebagian skenario RBAC — ke depannya saya ingin menambah test otomatis untuk semua kombinasi peran, serta load testing untuk memastikan performa tetap stabil di volume data yang lebih besar dari 1.250 baris dummy yang saya pakai sejauh ini.
